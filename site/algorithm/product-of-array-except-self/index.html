✖️ Product of Array Except Self

For each spot in a list, multiply everything except the number in that spot — and do it fast, without division, in one left-to-right pass and one right-to-left pass.

🧒 Explain it like I'm 10

The simple story

Imagine 4 friends sitting in a row, each holding a number card: 2, 3, 4, 5. You want to give each friend a new card that equals all the OTHER friends' numbers multiplied together — but they're not allowed to count their own card.

The slow way: for each friend, multiply everyone else one by one. That's a lot of repeated work. Here's a cleverer trick using two walks down the row:

  • Walk left → right. Keep a running "product so far" in your head, starting at 1. Before you update it, whisper to each friend: "everyone to your LEFT multiplied is ___." Then fold their card into your running product and move on.
  • Walk right → left. Reset your running product to 1. Now whisper: "everyone to your RIGHT multiplied is ___," and multiply that into the number you already gave them.

When both walks are done, each friend is holding (everyone on their left) × (everyone on their right) — which is everyone except themselves! 🎉 And you never had to divide.

The rule a kid can follow

  1. Give everyone a "1" to start.
  2. Walk left to right: tell each friend the product of all cards before them.
  3. Walk right to left: multiply in the product of all cards after them.
  4. Done — each friend now holds the product of everyone but themselves.

The engineer's view

Product of Array Except Self (LeetCode #238): given nums[], return answer[] where answer[i] = product of all elements except nums[i]. The constraints are the whole point: do it in O(n) without using the division operator, and the output array does not count toward extra space.

The trick is the prefix × suffix decomposition: for any index i, answer[i] = (∏ nums[0..i-1]) × (∏ nums[i+1..n-1]) — the product of everything to its left times everything to its right. Two linear sweeps compute these without ever multiplying nums[i] into its own result.

Why avoid division? The naive "total product ÷ nums[i]" is O(n) but breaks on zeros (division by zero, and a single zero makes the formula wrong for every non-zero slot). The prefix/suffix method sidesteps that entirely and handles any number of zeros for free.

Invariants, preconditions & edge cases

  • Invariant after pass 1: answer[i] holds the product of all elements strictly left of i (with answer[0] = 1).
  • Invariant during pass 2: a running scalar right holds the product of all elements strictly right of i; multiply it in, then update it.
  • One zero → only that index gets a non-zero answer; every other index is 0. The algorithm handles this naturally.
  • Two or more zeros → every answer is 0.
  • Overflow: products can be large; LeetCode guarantees the answer fits in 32-bit int, but intermediate products in other contexts may need long.
  • Negatives work unchanged — sign just flows through the multiplication.

Trade-offs & when NOT to use it

  • vs. division: if division is allowed AND no zeros are possible, the one-liner total/nums[i] is simpler — but fragile. Prefer prefix/suffix as the robust default.
  • vs. two helper arrays: functionally identical and easier to read; collapse into the output array only when space is the constraint.
  • Not applicable when you need cumulative products including self (that's a plain prefix-product scan).

Reference implementation (C#) — the left-to-right then right-to-left method

public int[] ProductExceptSelf(int[] nums)
{
    int n = nums.Length;
    int[] answer = new int[n];

    // Pass 1 — LEFT TO RIGHT: answer[i] = product of everything to the LEFT of i.
    answer[0] = 1;                          // nothing to the left of index 0
    for (int i = 1; i < n; i++)
        answer[i] = answer[i - 1] * nums[i - 1]; // carry the running left-product

    // Pass 2 — RIGHT TO LEFT: multiply in the product of everything to the RIGHT.
    int right = 1;                          // nothing to the right of the last index
    for (int i = n - 1; i >= 0; i--)
    {
        answer[i] *= right;                  // left-product × right-product
        right *= nums[i];                    // extend running right-product
    }

    return answer;
}

🔁 How it works, step by step

Let's run nums = [2, 3, 4, 5]. The expected answer is [60, 40, 30, 24] (e.g. answer[0] = 3·4·5 = 60).

Pass 1 — left to right (fill in the LEFT products)

  1. answer[0] = 1 (nothing is to the left of index 0).
  2. answer[1] = answer[0] · nums[0] = 1 · 2 = 2 (just the 2 on its left).
  3. answer[2] = answer[1] · nums[1] = 2 · 3 = 6 (2·3 on its left).
  4. answer[3] = answer[2] · nums[2] = 6 · 4 = 24 (2·3·4 on its left).

🌍 Where the prefix/suffix pattern is used in the real world

The specific puzzle is interview-famous, but the underlying prefix-product / prefix-sum (cumulative scan) pattern is everywhere — precompute running aggregates so each query becomes O(1) instead of O(n):

  • Prefix sums / range queries: the sum (or product) of any subarray [l, r] in O(1) after an O(n) precompute — the backbone of analytics dashboards, histograms, and "sum between dates" reports.
  • Image processing — summed-area tables (integral images): the 2-D version of prefix sums lets face-detection and blur filters read the sum over any rectangle in constant time.
  • Probability & ML: "leave-one-out" products — e.g. the chance an event happens given all factors except one — use exactly this except-self decomposition; also appears in computing gradients/Jacobians without recomputation.
  • Spreadsheets & finance: running totals, cumulative returns, and "contribution of each item to the whole" columns.
  • GPU / parallel computing: the scan (prefix-sum) primitive is a fundamental parallel building block (stream compaction, sorting, allocation) — the same left-to-right accumulation idea, parallelized.
  • Water-trapping / stock-span style problems: many array problems precompute "max/product/sum to the left" and "…to the right," then combine — the same two-pass shape as this algorithm.

📌 Cheat sheet

  • Goal: answer[i] = product of all elements except nums[i], in O(n), no division.
  • Key identity: answer[i] = (product of everything LEFT of i) × (product of everything RIGHT of i).
  • Pass 1 (L→R): answer[i] = answer[i-1] * nums[i-1], with answer[0]=1.
  • Pass 2 (R→L): keep scalar right=1; answer[i] *= right; right *= nums[i];
  • Space: O(1) extra — the output array holds the left products; a single variable holds the right.
  • Why no division: robust to zeros (1 zero → only that slot non-zero; ≥2 zeros → all zero).
